Privacy policy

whileAI browser extension. Last updated 17 September 2026.

whileAI never reads the AI's answers. Your prompts and timings stay in your browser. There is no account and no analytics. Three kinds of network request exist and none carries anything about you. All three are described below, with their exact fields.

What is stored, and where

Everything stays on your own machine, in the browser's extension storage (IndexedDB, chrome.storage.local, and chrome.storage.session for tab ids that are discarded when you close the browser). None of it is transmitted anywhere.

  • Response timings. When an answer started and finished, which AI it came from, and whether the tab was visible at the time.
  • Your settings. Which AIs you switched on.
  • Your prompt text, briefly. It is held only while it is being delivered to the AIs you chose, then deleted. Keeping a history is off by default and is yours to switch on.

What whileAI never does

  • Never reads or stores the AI's responses. It watches only whether an answer is still arriving, so it can time it.
  • Never sees, stores or transmits your passwords or login details. You sign in yourself, in your own browser.
  • Never solves or bypasses CAPTCHAs or verification checks. When a provider shows one, whileAI stops and tells you.
  • Never sends your prompts, the AI's answers, or your browsing anywhere.

The three times whileAI uses the network

All three are listed here rather than buried, because "no server at all" would not be strictly true, and a privacy policy that overstates itself is worse than one that explains itself.

  • Selector updates. Every few hours whileAI fetches a small public file describing where the send button and message box are on each AI site. These sites change often, and this is what lets a fix reach you without waiting for a store update. It is a plain download of a public file: no identifier, no prompt, nothing about you.
  • A breakage signal, when a site changes (since 0.9.0). The AI sites redesign their pages without warning, and then whileAI can no longer find the message box or the send button. When its own check sees that, it sends one message a day per site to ahmetaytar.com/whileai/health/ping containing exactly: the site's name (for example deepseek), which part broke (composer, sendButton, userMessage, answer), which backup selector is in use if any (a CSS selector from the public definition file, never text from the page), the definition version and the extension version. Never a prompt, an answer, a page URL or title, an account, a cookie, or any identifier. Sent without credentials; the reply is ignored. It exists so a fix can be written before you have to report the problem. Kept on this site for 14 days as per-site, per-day counts. You can turn it off in the extension's dashboard: Data → "Report when a site changes".
  • Activating a licence, once. whileAI is free and has no paid tier today, so this does not currently happen. It is described because the capability exists: if a paid tier is ever added, a licence key would be checked with the payment provider the single time you enter it, and the result remembered. It would not be re-checked while you work.

Which sites it runs on

Only these five, and no others: chatgpt.com, claude.ai, www.perplexity.ai, gemini.google.com, chat.deepseek.com. On each it reads the message box and the newest message, so it can copy your prompt across and time the reply.

Your data is yours

The dashboard can export everything as JSON or CSV, and delete everything at once. Removing the extension removes its storage with it.

Children

whileAI is not directed at children under 13 and collects nothing from anyone, of any age.

Changes

If this policy changes, the date at the top changes with it, and the the previous text is kept and available on request.
